## 1. 프로젝트 개요

### 한 줄 소개

현대적인 한국 동네를 탐험하고, 주민들의 고민을 해결하며, 숨어 있는 도깨비와 친구가 되는 브라우저 기반 3D 어드벤처 서비스.

### 기획 의도

펄어비스의 「도깨비(DokeV)」 트레일러에서 느껴지는 다음 감성을 웹에서 짧고 밀도 있게 경험하도록 만든다.

- 현대 한국 도시와 판타지의 결합
- 어린 시절의 모험과 발견
- 개성 있는 도깨비와의 만남
- 음악, 색채, 이동이 주는 활기
- 사진을 찍고 공유하고 싶은 장면

원작의 로고·캐릭터·음원·세계관을 복제하지 않고, 한국 설화와 현대 도시를 바탕으로 독자적인 이름, 캐릭터, 이야기, 비주얼을 구축한다.

## 2. 제품 목표

### 핵심 목표

사용자가 별도 설치 없이 웹에 접속해 5~8분 안에 하나의 완결된 모험을 경험하고, 첫 도깨비를 획득한 뒤 결과를 공유하게 한다.

### 핵심 플레이 루프

```text
동네 탐험 → 이상 현상 발견 → 주민/NPC 대화 → 단서 수집
→ 미니게임 또는 추격 → 도깨비와 만남 → 도감 등록 → 사진 촬영·공유
```

### 성공 기준

- 첫 화면에서 플레이 시작까지 10초 이내
- 방문자의 60% 이상이 월드에 진입
- 월드 진입 사용자의 40% 이상이 첫 퀘스트 완료
- 첫 퀘스트 완료 사용자의 20% 이상이 포토 모드 사용
- 데스크톱 60fps 목표, 모바일 최소 30fps 유지
- 치명적인 진행 불가 오류 없이 첫 번째 플레이 루프 완주 가능

수치는 비공개 알파 테스트 이후 실제 데이터에 맞춰 조정한다.

## 3. 타깃 사용자

### 주요 사용자

- 감성적인 3D 웹 경험을 좋아하는 10~30대
- 한국 설화, 캐릭터 수집, 가벼운 어드벤처에 관심 있는 사용자
- 긴 게임 설치 없이 짧은 체험을 원하는 모바일·PC 사용자
- 결과 화면이나 캐릭터 사진을 SNS에 공유하는 사용자

### 지원 환경

- 1순위: 최신 Chrome, Edge, Safari 데스크톱
- 2순위: iOS Safari, Android Chrome
- 입력: 키보드·마우스, 터치 UI
- 저사양 또는 WebGL 미지원 환경에는 2D 소개 화면 제공

## 4. 서비스 콘셉트

### 임시 명칭

`DokeV`

정식 명칭은 상표·도메인 중복 검토 후 확정한다.

### 세계관 초안

사람들의 바람과 잊힌 약속이 쌓이는 도시에는 눈에 보이지 않는 작은 존재들이 산다. 주인공은 오래된 부적이 달린 카메라를 우연히 얻고, 평범한 동네 곳곳에 숨어 있던 도깨비와 이상 현상을 볼 수 있게 된다.

도깨비는 포획하는 대상이 아니라 각자의 사연을 해결하면서 친구가 되는 존재다. 도깨비와 가까워질수록 새로운 이동 능력이나 탐색 능력을 사용할 수 있다.

### 비주얼 키워드

- 노을이 비치는 한국형 주택가
- 간판, 전깃줄, 골목, 편의점, 분식집, 놀이터
- 부적, 단청, 노리개, 자개 등 전통 모티프의 현대적 재해석
- 선명한 청록·주황·보라 포인트 컬러
- 둥글고 장난감 같은 실루엣
- 현실적인 구조 위에 과장된 빛, 파티클, 바람 표현

### 톤앤매너

- 밝고 활기차되 유아적으로 보이지 않는다.
- 전투보다 발견, 장난, 관계 형성을 강조한다.
- 설명보다 움직임과 환경 연출로 세계관을 전달한다.
- UI는 게임 HUD보다 생활 앱과 스티커북의 중간 느낌을 지향한다.

## 5. MVP 범위

### 반드시 포함

체크는 **코드에 있고 테스트가 지킨다**는 뜻이다. 사람이 플레이해 확인했다는
뜻이 아니다 — 조작감·연출 타이밍·소리는 아직 아무도 보지 않았다
([README](../README.md) 「사람이 봐 줘야 하는 것」).

- [x] 시네마틱 랜딩 — 시작 화면 그림 한 장(`title-street.webp`, 137KB) 위에 시작 버튼 하나.
      조작법·설정은 작은 글로 물러나 있다
- [x] 게스트 플레이 — 로그인 없음
- [x] 캐릭터 프리셋 선택 및 이름 설정 — 시작 화면에서 고른다. 이름은 선택이며 완주 화면과 저장 파일 이름에 쓰인다
- [x] 3D 동네 — 6×6 블록, 282m
- [x] 걷기, 달리기, 점프, 그리고 **탈것 3종**(킥보드·자전거·스케이트보드) 이동
- [x] 키보드·마우스 및 모바일 터치 조작
- [x] NPC 대화 — 주민 가까이에서 `T`(터치는 「살펴보기」). 한 줄짜리 대사, 분기 없음
- [x] 조사 가능한 오브젝트 — 간판을 살펴보면 무슨 가게인지 알려 준다(주민 말 걸기와 같은 키)
- [x] 첫 번째 도깨비 퀘스트 — 5단계 + 보스 여정
- [x] 단서 수집 — 도시에 남은 흔적 세 자리를 살펴본다(지도에 표시). **미니게임은 없다** — 골목 추격 대신 고물 대장 전투가 그 자리를 맡는다
- [x] 도깨비 획득 연출 — 자리 빛기둥과 만남 알림
- [x] 도깨비 도감 — 해금 조건과 진행도 표시
- [x] 포토 모드 및 이미지 저장 — 사진(PNG)과 클립(최대 30초)
- [x] 진행 상황 자동 저장 — 여정 단계·처치 수·보스 처치·만난 도깨비
- [x] 기본 이벤트 분석과 오류 수집 — 호출 지점은 심어 두었고 수집 서버가 없어 기본 sink는 아무것도 보내지 않는다

### MVP에서 제외

> 「다수의 이동수단」이 여기 있었다. 킥보드·자전거·스케이트보드 셋을 넣으면서
> 뺐다 — 제외 목록에 남겨 두면 문서가 코드를 부정한다.

- 실시간 멀티플레이
- 자유로운 채팅
- 복잡한 전투 시스템
- 전체 도시 규모의 오픈월드
- 자유 조합형 3D 캐릭터 제작
- 유료 아이템과 결제
- 네이티브 앱

## 6. 첫 번째 버티컬 슬라이스

### 사용자 경험

사용자는 노을이 지는 골목에서 깨어난다. 놀이터 방향에서 들리는 이상한 소리를 따라가면서 주민들과 대화하고, 세 개의 흔적을 조사한다. 흔적을 모두 모으면 그림자 속 도깨비가 나타나고 골목 추격 미니게임이 시작된다. 미니게임을 마치면 도깨비의 사연이 드러나며 친구가 된다. 마지막으로 도깨비와 사진을 찍어 결과 이미지를 저장한다.

### 예상 플레이 시간

5~8분

### 공간 구성

1. 시작 골목: 이동 튜토리얼
2. 편의점 앞: 첫 NPC와 세계관 소개
3. 분식집 골목: 첫 번째 단서
4. 주택가 옥상: 두 번째 단서와 점프 동선
5. 놀이터: 세 번째 단서와 도깨비 등장
6. 광장: 추격 미니게임 종료 및 포토 모드

### 첫 도깨비 초안

- 임시 이름: `몽실`
- 외형: 구름과 빗자루를 섞은 둥근 실루엣
- 성격: 장난이 많지만 낯을 가림
- 사연: 아이들과 다시 놀고 싶어 놀이터 물건을 몰래 옮김
- 능력: 짧은 시간 주변의 숨겨진 흔적을 빛나게 함

## 8. 기능 요구사항

### 계정과 저장

- 첫 진입은 게스트 세션으로 시작한다.
- 브라우저 로컬 저장소에 설정과 임시 진행을 저장한다.
- 로그인 도입 시 게스트 진행을 계정에 병합한다.
- 저장 항목: 캐릭터 설정, 퀘스트 상태, 획득 도깨비, 옵션.

### 퀘스트

- 퀘스트는 데이터 기반으로 정의한다.
- 조건, 대화, 보상, 다음 단계가 코드와 분리되어야 한다.
- 중간 이탈 후 마지막 완료 단계부터 재개할 수 있어야 한다.

### 콘텐츠 관리

- 초기에는 JSON/TypeScript 데이터로 관리한다.
- 콘텐츠가 늘어나면 운영자가 NPC 대사, 퀘스트, 이벤트 기간을 수정하는 어드민을 추가한다.

### 분석 이벤트

- `landing_view`
- `experience_start`
- `world_loaded`
- `tutorial_complete`
- `clue_collected`
- `quest_complete`
- `dokebi_unlocked`
- `photo_mode_opened`
- `photo_saved`
- `share_clicked`

## 9. 기술 설계 초안

### 권장 스택

| 영역 | 기술 |
|---|---|
| 웹 애플리케이션 | Next.js, TypeScript |
| 3D | Three.js, React Three Fiber |
| 물리·충돌 | Rapier |
| UI 스타일 | Tailwind CSS, 프로젝트 디자인 토큰 |
| UI 애니메이션 | Motion 또는 GSAP |
| 클라이언트 상태 | 없음 — 공유 가변 객체를 렌더 루프가 직접 읽는다 (18절 참조) |
| 서버 API | 초기에는 Next.js 서버 기능, 필요 시 별도 분리 |
| 데이터베이스 | PostgreSQL |
| 3D 제작 | Blender, glTF/GLB 파이프라인 |
| 배포 | CDN 지원 웹 호스팅, 객체 스토리지, 관리형 DB |

라이브러리의 구체적인 버전은 프로젝트 생성 시점의 안정 버전을 검토한 뒤 고정한다.

### 구조 원칙

- UI와 3D 월드 로직을 분리한다.
- 퀘스트·대화·도깨비 데이터는 렌더링 코드와 분리한다.
- 월드는 구역 단위로 로딩·해제할 수 있어야 한다.
- 게임 진행 상태는 직렬화 가능한 데이터로 관리한다.
- 모바일 품질 단계를 별도로 둔다.

### 디렉터리 구조 (실제)

계획이 아니라 지금 코드의 모습이다. `tests/projectStructure.test.ts`가 이 표를
실제 파일과 대조한다.

```text
src/
  app/                  # 라우트 — 랜딩(/)과 월드(/play)
  components/
    hud/                # 월드 HUD, 도감, 지도, 알림, 터치 조작
    title/              # 시작 화면
  game/
    core/               # 수학·색 등 의존성 없는 유틸
    config/             # 튜닝 상수
    world/              # 도시 생성·렌더, 텍스처, 구역, 시간대, 교통, 군중
    player/             # 이동, 캐릭터 자세, 포토 포즈
    dokebi/             # 동료 동작·렌더, 명부, 자리, 만남 연출
    combat/             # 전투 시뮬, 적 렌더, 투사체
    quest/              # 퀘스트 실행기·내용, 대사
    scene/              # R3F 씬 조립과 카메라
    systems/            # 입력·조작 정본, 저장, 설정, 오디오, 캡처, 지도, 품질, 분석
tests/                  # 순수 로직 + 정합성 검사
public/                 # SVG 아이콘뿐 — 모델·텍스처·오디오 파일은 두지 않는다
```

**`public/`에 에셋 디렉터리를 만들지 않는다.** 텍스처는 런타임 캔버스 합성,
사운드는 Web Audio 합성, 모델은 프리미티브 조합이다. 예전 초안에는
`public/models`, `public/textures`, `public/audio`가 있었는데 그건 이 프로젝트가
스스로 금지한 것을 안내하는 셈이었다.

계획 초안에 있었지만 만들지 않은 것: `npc/`(적은 combat에, 시민은 world에),
`content/`(퀘스트 내용은 quest/questContent.ts), `stores/`(전역 상태 없이 공유
가변 객체를 쓴다), `styles/`(globals.css 하나).

## 10. 성능 예산

- 초기 진입에 필요한 다운로드: 10~15MB 목표
- 첫 의미 있는 화면: 일반적인 모바일 네트워크에서 3초 이내 목표
- 3D 월드 진입: 10초 이내 목표
- 데스크톱: 60fps 목표
- 중급 모바일: 30fps 이상
- 장시간 플레이 시 메모리 누수 방지
- 초기 구동에 필요하지 않은 모델·음원은 지연 로딩

### 최적화 원칙

- GLB 모델과 Meshopt 또는 Draco 압축
- KTX2 텍스처와 해상도 단계 제공
- 정적 조명과 그림자는 가능한 범위에서 베이크
- 반복 오브젝트는 인스턴싱
- 화면 밖 오브젝트 컬링
- 구역 단위 에셋 스트리밍
- 모바일에서 그림자, 반사, 파티클 품질 자동 축소

## 11. 접근성 및 사용성

- 모든 핵심 기능을 키보드로 조작 가능하게 한다.
- 카메라 흔들림과 모션 블러를 끌 수 있게 한다.
- 자막과 사운드 시각화 옵션을 제공한다.
- 색상만으로 퀘스트 상태를 구분하지 않는다.
- 터치 버튼 크기와 간격을 모바일 기준에 맞춘다.
- 포토 모드 외의 주요 화면에서 텍스트 대비를 확보한다.

## 12. 운영 및 정책

- 공식 서비스로 오인되지 않도록 독자 IP임을 명확히 표시한다.
- 원작의 로고, 캐릭터, 영상, 음원, 고유 설정을 사용하지 않는다.
- 닉네임 금칙어와 신고 수단을 마련한다.
- 계정 기능 도입 시 개인정보처리방침과 이용약관을 제공한다.
- 오류 추적 도구에는 비밀번호나 불필요한 개인정보를 기록하지 않는다.
- 공개 전 명칭·로고·도메인의 상표 충돌 여부를 검토한다.

### 동작하는 것

| 영역 | 내용 |
|---|---|
| 화면 | 시작 화면(`/`), 월드(`/play`). 랜딩에는 3D를 싣지 않는다 |
| 도시 | 6×6 구역, 282m×282m. 절차적 생성 + 구역 스트리밍 + **구역 성격 9종** — 달빛 광장·번화가·고물 공사장·노을 시장·언덕 주택가·옛 마을·너른 공원·안개 숲·윤슬 해안. 성격은 고리 거리가 아니라 `zones.ts`의 **손으로 그린 6×6 지도**가 정한다 — 광장을 번화가가 감싸고 네 방향으로 각각 다른 동네가 열린다. 구역마다 필지 수·층수·공터 비율·바닥 색·나무 밀도가 다르다. **공사장은 건물을 세우지 않는다** — 대장이 그 한가운데에 서고, 34m 블록이 통째로 싸움터가 된다 |
| 비주얼 | **벽면의 결**(얼룩 40점 + 층 이음매, `world/grain.ts`) — 배경이 단색 면이면 매끈한 캐릭터가 떠오르지 않는다. 해상도는 그대로 두고 같은 크기 안에서 결만 넣었다 · 한글 간판 아틀라스, 차양, 현수막, 1층 유리, 아스팔트·보도블록 텍스처, 인도 소품, 전깃줄 |
| 시간대 | **여명·한낮·노을·밤** — 조명·하늘·안개가 함께 바뀐다. 창문·가로등·전조등이 밤에 켜진다 |
| 이동 | 걷기 3.2 / 달리기 7.4 m/s, 코요테 타임, 점프 버퍼, 이단 점프, 활강, **그래플** |
| 물 | **타고 있으면 바다로 나간다** — 가장자리 밖에서 수면 높이에 얹혀 달리고, 뭍으로 돌아오면 원래대로다(`world/waterRide.ts`). 두 발로는 못 나간다(걸어 들어가면 수영이고 그건 다른 게임이다). 60m 상한이 있다 — 없으면 수평선을 향해 영영 나간다 |
| 탈것 | **6종** — 킥보드 12.5 · 장난감 자동차 13.5 · 보드 15.5 · 자전거 18 · **조랑말 10.5** · **제트스키 21** m/s. 앞의 셋과 자전거는 거리 거치대(도시 구역), 보드는 늘 들고 다니고, 조랑말은 자연 구역 풀밭, 제트스키는 해안에 서 있다. 전부 절차적 도형이다. 조랑말은 네 다리가 대각선으로 엇갈린다. 제트스키만 물 위로 나간다 |
| 카메라 | 속도 연동 FOV·거리·**높이**, 시선 선행, 착지 흔들림, 건물 관통 방지. 멈추면 낮게 붙고(1.55m) 달리면 올라가 멀어지며(2.05m), **로봇이 붙으면 물러나 전장이 보이고**, **언덕 마루처럼 트인 곳에서는 더 올라가 도시 너머가 보이며**, **무언가를 타면 낮아지고 붙어 차체가 화면 아래에 들어온다.** 계산은 `cameraRig.ts` 순수 함수 |
| 캐릭터 | 절차적 실루엣 + 6종 이동 자세 + 공격 동작·감정 표현·포토 포즈, 착지 스쿼시. **외형 4종**을 시작 화면에서 고른다 |
| 도깨비 | **4종**(초롱·그을음·물비늘·자정). 찾아가 **손을 내밀어야** 해금되고(지나가기만 해서는 안 열린다. 자리에 서면 화면이 「손을 내밀어 보자」로 알린다 — 이름은 밝히지 않는다) **만난 모두가 함께 따라온다**. 능력 규칙이 서로 다르고 효과는 합쳐진다. 능력을 쓰면 **동료 빛이 닿는 곳의 흔적이 바닥에 떠오른다** — 범위가 도깨비마다 달라 자정은 넓게, 그을음은 오히려 좁게 드러낸다. 해금 조건은 처치 수·첫 여정 완주·**고물 대장 처치**로 나뉜다 — 절정을 넘긴 보상이 수집으로 이어진다 |
| 도감 | 만난 도깨비·해금 조건·진행률. 잠긴 항목은 실루엣으로 표시. **만난 도깨비에게는 두 줄짜리 사연**이 붙는다 — 어느 사물에서 나왔고 왜 그렇게 구는지. 못 만난 도깨비의 사연은 **화면으로 넘어가지도 않는다**(`storyFor`) |
| 알림 | 조건을 채우면 **「찾아갈 자리가 생겼다」**(이름은 밝히지 않는다), 실제로 만나면 **「새 도깨비를 만났다」** |
| 완주 화면 | 걸린 시간·최고 속도·멈춘 로봇·**만난 도깨비 수**. 남은 수집물이 있다는 것을 마지막 화면이 알려 준다 |
| 지도 | **전체 지도**(북쪽 고정, 구역 색). 목표·도깨비 자리·보스 표시. 표식은 **반경 80m** 안의 것만 센다. 미니맵은 걷어냈다 — 늘 떠 있는 판은 「세계가 먼저, UI는 나중에」와 어긋나고, 원작 트레일러 93장에도 없다. 대장 방향은 화살표가 맡는다 |
| 생활감 | 보행자·주행 차량 (인스턴싱, 거리 컬링). 보행자는 **걷기·마주 보고 대화·앉기·서 있기** 넷으로 갈리고, **밤에는 거리가 빈다**(한낮의 25%). 트레일러 프레임에서 낮 거리에는 걷기만 하는 인물이 사실상 없고 밤에는 1명으로 뚝 떨어진다 — 수가 아니라 **행동의 종류**가 도시를 살아 있게 한다. `R`로 춤을 추면 **반경 9m 안 시민이 하던 일을 멈추고 나를 보며 함께 흔든다** — 멈추면 그 자리에서 각자 하던 일로 돌아간다. **옆을 지나가면 쳐다보고, 가까이서 전투가 붙으면 앉아 있던 사람도 일어나 물러선다** — 트랙 두 방향 중 멀어지는 쪽으로 |
| 전투 | 근접형 + 사수형 로봇 + **미니 보스**(예고 링·비틀거림·빈틈). 플레이어 체력·무적·회복·부활 |
| 타격 | 색종이 파티클 + **휘두른 자국**. 근접 무기가 부채꼴을 쓸고 지나간 자리에 넓적한 자국이 남았다 사라진다 — 프레임의 참격이 불꽃이 아니라 **붓자국**이었다. 자국의 폭·각도는 판정 부채꼴 안에서만 정해진다(`player/swingTrail.ts`) |
| 로봇의 정체 | 로봇·대장 **가슴에 살아 있는 색의 점**이 박혀 있고, 눕히면 그 빛이 **곧게 떠올라 잦아들고**, 동료가 처음 세 번까지 그것에 대해 한 줄 말한다(`combat/emberRelease.ts`). 색종이는 중력을 받아 흩어지므로 둘이 구분된다 — 새 시스템 없이 「저 안에 무언가 갇혀 있었다」가 화면에 생긴다 |

### 지키고 있는 제약

- **외부 에셋은 둘 — 캐릭터(`public/character.glb`, 1.1MB)와 시작 화면 그림
  (`public/title-street.webp`, 137KB).** 그 밖의 GLB·오디오·
  이미지는 받지 않는다 — 텍스처는 런타임 캔버스 합성, 사운드는 Web Audio 합성,
  도시·도깨비·적은 프리미티브 조합이다. 목록에 없는 에셋은 검사가 막는다.
- **초기 다운로드 128KB gzip** (공통 번들, 예산 150KB). three.js 청크 314KB는
  `/play`에서만 받는다 — `tests/bundleBudget.test.ts`가 둘 다 지킨다.
- 반복 오브젝트는 전부 InstancedMesh. 난수는 시드 고정.
- 매 프레임 setState 금지 — 공유 가변 객체를 렌더 루프가 직접 읽는다.
- 파일 800줄 상한. 넘으면 분할한다 — `WorldHud`를 두 번, `GameScene`을 한 번 쪼갰다.
  이제 `tests/fileSize.test.ts`가 센다.
- 광장 시작 지점 실측(개발 빌드, 자동 품질 `high`, 후처리 켜짐): 드로우콜 **73**,
  삼각형 **209,324**, 힙 **51MB**. 드로우콜이 예전(95)보다 **줄어든** 이유는
  그림자 카메라를 도시 전체에서 플레이어 주변 62m로 좁혔기 때문이다 — 그림자
  패스에 올라가는 물체가 함께 줄었다. 삼각형이 는 것은 하늘 돔과 GLB 캐릭터다.
  후처리는 풀스크린 삼각형 넷을 더한다.
  fps는 브라우저 자동화로 잴 수 없다 — 사람이 봐야 한다.
- 테스트 **2909개 / 157 파일**. 순수 로직 + **배치 정합성** + **대본·무작위 플레이 시뮬레이션**을 검증한다.
